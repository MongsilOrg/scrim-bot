# 스크림 결과 CSV 자동 전달 설계

관리자가 게임에서 "결과 내려받기"를 누른 뒤 CSV를 손으로 디스코드에 올리는 일을 없애기 위한 조사와 설계입니다.
코드는 바꾸지 않았습니다.

표시 기준

| 표시 | 뜻 |
|---|---|
| 확인 | 코드에서 직접 읽은 사실입니다 |
| 추정 | 코드 밖 동작이나 문서 기억에 기대는 내용입니다 |
| 미확인 | 이번 조사로 확인하지 못했습니다 |

## 2. labs의 대회 라운드 CSV 처리

### 2.1 화면과 API

| 항목 | 내용 | 근거 | 표시 |
|---|---|---|---|
| 업로드 화면 | 대회 화면 `/er/t/{코드}`. 운영자만 "CSV 올리기", "CSV 교체" 버튼과 창 전체 드래그 앤 드롭이 보입니다 | `src/er/components/t/TournamentApp.tsx`, `Rounds.tsx` | 확인 |
| 파일 고르기 | `accept=".csv,text/csv"`. 브라우저에서 확장자 `.csv` 또는 형식 `text/csv`만 거릅니다 | `TournamentApp.tsx` | 확인 |
| 쓰기 API | `POST /api/t/{코드}`, 본문 `{ op: "add_csv", group, files: [{ name, text }], round? }` | `src/app/api/t/[code]/route.ts`, `src/er/lib/view.ts` | 확인 |
| 서버의 파일 이름 검사 | 없습니다. 이름은 120자로 잘라 기록에만 남깁니다 | `src/er/server/tournament.ts` `add_csv` | 확인 |

| 응답 | 파일별 실패도 HTTP 200에 `ok: false`, `errors`로 돌아옵니다. 호출하는 쪽은 상태 코드가 아니라 `ok`를 봐야 합니다 | `tournament.ts` `applyOp` | 확인 |

### 2.2 인증

| 경로 | 방식 | 쓰기 | 표시 |
|---|---|---|---|
| 로그인 세션 | 디스코드 OAuth 로그인 쿠키, 7일 유효. 쓰기 요청은 Origin이 사이트 주소와 같아야 하고, 그 대회의 개최자나 운영자여야 합니다 | 됨 | 확인, `src/er/server/auth.ts`, `http.ts` `guardWrite` |
| 봇 토큰 `/api/bot` | `x-bot-token` 헤더를 서버 환경변수 하나와 비교합니다. 대회별 토큰이 아니고, 틀리면 404로 숨깁니다 | 안 됨, GET만 3개 | 확인, `src/er/server/board.ts` `botAuthorized` |
| 봇 경로 목록 | `/api/bot/t/{코드}`, `/api/bot/t/{코드}/image`, `/api/bot/users/{ID}/tournaments` | 조회 전용 | 확인 |
| 기록 남기기 | 모든 쓰기는 `logs`에 사용자 이름을 남깁니다. 토큰으로 쓰려면 누가 쓴 것으로 남길지 정해야 합니다 | - | 확인, `tournament.ts` `bump` |
| `/api/bot`을 쓰는 봇 | labs README의 "몽실봇"입니다. scrim-bot에는 labs를 부르는 코드가 없습니다 | - | 확인. 몽실봇이 어느 레포인지는 미확인 |

정리하면, 지금 labs에는 브라우저 로그인 없이 CSV를 올릴 수 있는 경로가 없습니다.
세션 쿠키를 관리자 PC 프로그램에 옮겨 쓰는 방법은 계정 전체 권한이 새므로 쓰지 않습니다.

### 2.3 중복, 라운드 번호, 제한

| 항목 | 내용 | 표시 |
|---|---|---|
| 중복 판정 | 대회 안에서 `gameId`가 같으면 거절합니다. "이미 N라운드에 올린 경기입니다". DB에도 지워지지 않은 기록 기준 고유 색인이 있습니다 | 확인, `db.ts` `rounds_game` |
| 같은 요청 안 중복 | "함께 올린 파일 중에 같은 경기의 CSV가 있습니다"로 거절합니다 | 확인 |
| 라운드 지정 | `round`는 파일이 정확히 1개일 때만 씁니다. 그 라운드에 기록이 있으면 지우고 바꾸며 되살리기를 제공합니다 | 확인 |
| 자동 배정 | `round`가 없으면 `gameId` 순으로 정렬해 비어 있는 가장 앞 라운드에 넣습니다 | 확인 |
| 조 지정 | `group`은 0부터의 번호이고 화면 이름은 A, B, C 순입니다 | 확인, `rules.ts` `groupLabel` |
| 파일 크기 | 파일당 200KB | 확인, `LIMITS.csvBytes` |
| 한 번에 | 파일 24개, 본문 6MB | 확인 |
| 줄 수 | 데이터 96줄 | 확인 |
| 대회 설정 | 조 8개, 라운드 12개, 순위 점수표는 조당 8팀 | 확인 |
| 요청 빈도 | 사용자당 분당 쓰기 120번, 봇 조회 분당 1200번. 메모리 기준이라 서버를 다시 켜면 초기화됩니다 | 확인, `src/limits.ts` |
| 동시 업로드 | 쓰기는 트랜잭션 안에서 처리하고 고유 색인이 있어 같은 경기는 한 번만 들어갑니다 | 확인. 동시 요청 순서는 추정 |

## 3. scrim-bot의 지금 흐름

| 항목 | 내용 | 근거 | 표시 |
|---|---|---|---|
| CSV 감지 | 조별 채널에 사람이 `.csv` 첨부를 올리면 처리합니다 | `bot/events.py` `on_message` | 확인 |
| 봇 메시지 | `message.author.bot`이면 바로 무시합니다 | `bot/events.py` `on_message` | 확인 |
| 웹훅 메시지 | 디스코드가 웹훅 메시지 작성자를 봇으로 표시하므로 위 조건에 걸려 무시될 것입니다 | - | 추정 |
| 집계 범위 | 오늘 0시(KST) 이후 채널 기록 200개에서 CSV를 모두 다시 읽습니다. 작성자는 가리지 않습니다 | `services/score_aggregation.py` `collect_today_csv_data` | 확인 |
| 중복 | 같은 `gameId`는 먼저 올라온 하나만 씁니다 | 같은 곳 | 확인 |
| 라운드 번호 | 오늘 CSV 개수를 라운드 수로 씁니다. `gameId` 순으로 정렬합니다 | `bot/events.py` | 확인 |
| 결과 응답 | 팀별 누적 점수표 이미지를 채널에 올립니다. 4라운드째에는 게임 ID 목록을 채널과 백업 채널에 올립니다 | `bot/events.py` | 확인 |
| 다른 용도 | `/방코드`가 마지막 CSV의 실험체로 금지 목록을 만듭니다 | `commands/room_code.py`, `score_aggregation.py` | 확인 |
| 결과 저장 | 결과는 채널 메시지에만 있습니다. 조편성 기록 파일에는 결과를 쓰지 않습니다 | `utils/scrim_history.py` | 확인 |
| 조와 채널 | 환경변수 `GROUP_CHANNEL_IDS`로 조 문자와 채널을 묶습니다. 조당 8팀, 하루 4라운드 | `config/settings.py` | 확인 |

중요한 점은 scrim-bot의 점수표와 금지 목록이 **조별 채널에 CSV가 올라와 있어야** 동작한다는 것입니다.
CSV를 labs로만 보내면 scrim-bot 기능이 멈춥니다.

## 4. 자동 전달 방식 비교

| 구분 | A. PC 프로그램 → labs API | B. PC 프로그램 → 디스코드 웹훅 | C. scrim-bot이 디스코드 첨부를 labs로 전달 |
|---|---|---|---|
| 요약 | 파일 갱신을 감지해 labs에 바로 올립니다 | 파일 갱신을 감지해 조별 채널 웹훅으로 올립니다 | 채널에 올라온 CSV를 봇이 labs에 넘깁니다 |
| 사용자 불편 해소 | 됨. 단 디스코드에는 안 올라갑니다 | 됨 | 안 됨. 디스코드 업로드는 여전히 손으로 합니다 |
| scrim-bot 점수표 | 따로 디스코드에도 올리지 않으면 멈춤 | 유지. 웹훅 메시지를 받도록 고쳐야 합니다 | 유지 |
| 관리자 할 일 | 프로그램 설치, 대회 코드와 업로드 토큰 입력, 조 선택 | 프로그램 설치, 조별 웹훅 주소 입력 | 없음. 지금처럼 올립니다 |
| 설치와 배포 | 중간. 토큰 입력 화면과 갱신 배포가 필요합니다 | 낮음. PowerShell 스크립트 한 개로도 됩니다 | 서버 배포만 합니다 |
| labs 변경 | 토큰 쓰기 경로와 토큰 관리 화면 | 없음 | 봇 쓰기 경로 |
| PC에 두는 비밀값 | 대회 업로드 토큰 | 웹훅 주소 | 없음 |
| 비밀값이 새면 | 그 대회에 아무 CSV나 넣고 라운드를 덮어씁니다 | 그 채널에 아무 글이나 올립니다 | 해당 없음 |
| 권한 회수 | labs에서 토큰 폐기 기능을 새로 만들어야 합니다 | 디스코드 채널 설정에서 웹훅 삭제 | 해당 없음 |

### 4.1 오작동 경우

| 경우 | A | B | C |
|---|---|---|---|
| 같은 파일 재저장 | labs가 `gameId`로 거절합니다. 프로그램도 내용 해시로 다시 보내지 않아야 합니다 | 프로그램이 해시로 막지 않으면 채널에 같은 파일이 또 올라갑니다. 집계는 `gameId`로 한 번만 셉니다 | labs가 거절합니다 |
| 저장 중 감지 | 덮어쓰는 도중 이벤트가 오면 반쪽 파일을 읽습니다. 몇 초 기다렸다가 필수 열과 `gameId`를 확인한 뒤 보냅니다 | 같음 | 해당 없음 |
| 다른 게임 결과 | 필수 열만 맞으면 labs가 다음 빈 라운드에 넣습니다 | scrim-bot이 집계에 넣습니다 | 같음. 봇이 오늘 조 명단과 닉네임을 대조해 걸러낼 수 있습니다 |
| 여러 관리자 동시 사용 | 같은 경기는 한 번만 들어갑니다. 다른 조 결과를 잘못된 조로 보낼 수 있습니다 | 같은 경기는 집계에서 한 번만 셉니다. 웹훅을 잘못된 조로 설정하면 그 조 점수표가 틀어집니다 | 올린 채널이 곧 조라서 조 혼동이 가장 적습니다 |
| 결과 내려받기를 안 누름 | 아무 일도 없습니다 | 아무 일도 없습니다 | 아무 일도 없습니다. 봇이 방코드 공지 수와 CSV 수 차이로 알림을 줄 수 있습니다 |
| 라운드 번호 | `round` 없이 보내면 빈 앞자리부터 채웁니다. 늦게 온 앞 경기가 있으면 순서가 어긋날 수 있습니다 | scrim-bot은 매번 `gameId` 순으로 다시 셉니다 | A와 같음 |

### 4.2 SmartScreen과 백신

| 형태 | SmartScreen | 백신 오탐 | 표시 |
|---|---|---|---|
| 서명 없는 exe 트레이 프로그램 | 내려받은 파일에 "알 수 없는 게시자" 경고가 뜹니다 | 파일 감시와 HTTP 전송, 자동 시작 조합은 오탐 후보입니다. PyInstaller 묶음은 특히 잦습니다 | 추정 |

## 5. 추천안

**B와 C를 합칩니다.**
PC에는 웹훅으로 조별 채널에 올리는 작은 스크립트를 두고, labs 전달은 scrim-bot이 서버에서 합니다.

| 이유 | 내용 |
|---|---|
| 지금 흐름 유지 | 점수표, 금지 목록, 게임 ID 기록이 그대로 동작합니다 |
| PC 비밀값 최소 | 관리자 PC에는 채널 하나에만 글을 쓰는 웹훅 주소만 둡니다. 디스코드에서 바로 지울 수 있습니다 |
| labs 토큰 보호 | labs 쓰기 토큰은 scrim-bot 서버에만 둡니다 |
| 배포 쉬움 | 1단계는 PowerShell 스크립트라 설치 프로그램이 필요 없습니다 |
| 단계적 도입 | B만 먼저 써도 사용자 불편은 풀리고, C는 labs 쪽 준비가 된 뒤 켭니다 |

### 5.1 구현 범위

| 단계 | 범위 | 제외 |
|---|---|---|
| 1. PC 스크립트 | 결과 파일 감시, 몇 초 기다림, 필수 열과 `gameId` 확인, 마지막으로 보낸 `gameId`와 해시 비교, 웹훅으로 파일 전송, 실패 시 재시도와 알림 창 | 트레이 아이콘, 자동 갱신 |
| 2. scrim-bot 수신 | 등록한 웹훅에서 온 CSV를 사람 업로드와 같게 처리 | 다른 봇 메시지 |
| 3. labs 전달 | 오늘 조별 채널과 labs 대회 코드를 묶고, 새 `gameId`만 labs에 보내고, 결과를 채널에 짧게 알림 | labs 대회 자동 생성 |
| 4. 선택 | 서명한 트레이 프로그램, 결과 미업로드 알림 | - |

### 5.2 labs 변경

### 5.3 scrim-bot 변경

| 파일 | 변경 |
|---|---|
| `bot/events.py` | `author.bot` 검사 앞에서 허용한 웹훅 ID의 메시지는 통과. 처리 뒤 labs 전달 호출 |
| `config/settings.py`, `.env.example`, README | labs 주소, labs 쓰기 토큰, 허용 웹훅 ID 목록 |
| `services/labs_api.py` 새로 만듦 | labs 쓰기 경로 호출, 응답의 `ok`와 `errors` 해석, 시간 초과와 재시도 |
| 명령 추가 | 관리자가 오늘 조별 채널에 labs 대회 코드를 연결하는 명령. 저장은 하루 단위 |
| 집계 보강 | 오늘 조 명단과 CSV 닉네임 겹침이 적으면 경고 |
